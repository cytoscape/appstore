Service Apps

Service Apps provide backend functionality that can be accessed by Cytoscape through exposed service endpoints.

Before you submit

Make sure your app:

  • Provides a valid service entry point and exposes the endpoints required by the app.
  • Has a consistent app identity across your application configuration and service definition.
  • Defines the required service metadata and configuration.
  • Uses valid endpoint paths and HTTP methods for all exposed services.
  • Does not include unnecessary source files, development dependencies, or other files that are not required to run the service.

Steps

  1. Build your service app. Prepare your production-ready service and make sure all required endpoints are available.
  2. Package your service. Create the required application bundle containing your service files and configuration. Make sure the required entry point and configuration files are located at the expected paths.
  3. Go to the Service App submission form.
  4. Fill out the form:
    • App name
    • Version
    • Author(s)
    • Description (optional)
    • License
    • Tags (optional, comma-separated)
    • Upload your service bundle
  5. Submit. The Store validates your service bundle and its configuration automatically. If validation fails, you'll see the specific error on the form — fix it and resubmit.
  6. Confirm your submission on the confirmation page that follows.
  7. Wait for review. Your submission enters the pending queue for review before publication. You'll be notified of the outcome.

If you need to resubmit

If your submission is rejected or fails validation, you can resubmit the same version number. The version is not permanently blocked by a rejected submission. Only published versions are locked.

Common rejection reasons

  • Invalid or inconsistent app identity
  • Missing or invalid service entry point
  • Missing or invalid service configuration
  • Invalid endpoint definitions
  • Service endpoints do not match the declared configuration
  • Missing required files from the service bundle
  • Bundle contains unnecessary or unsupported files
  • Bundle contains unsafe paths (e.g. ../)
  • Bundle exceeds the maximum allowed size
